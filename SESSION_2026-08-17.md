Everything here was verified against the running server, the live `369application` database, or
the tablet. Where something is built but unproven, it says so.

The through-line of the day: **the server was already sending the answer and the app was not
reading it.** That is the same defect five times over — invoice reversal reasons, the estimate

## 1. Client Invoices — `0d46e00`

`8e0c3e0` rebuilt the web invoice screen and never touched the app.

**The biggest find was not a gap but a break, and it predates that commit.** `paidFields` was a
`const` declared *below* both the list-mode and detail-mode early returns, so it was only ever
initialised in **create** mode, where nothing calls it. `Mark Paid` and `Revert` are list-row
buttons — both threw `paidFields is not a function` the instant they were tapped. Detail mode has
no Mark Paid button at all. **So marking an invoice paid was impossible from the app, in every
mode.** Verified against the committed file: list return at line 341, the `const` at 841. It is a
hoisted function declaration now.

Also fixed:
- **Revert could never succeed.** `action_mark_unpaid` raises without a reason; the field was
  labelled `Note (optional)`. Now required, validated client-side, and the reason is rendered —
  a red line on the list row and a banner on the invoice, both sides, because `unpaid_reason`
  exists to be published in a way `payment_notes` deliberately is not.
- **Claimed invoices reached no payment filter.** The server's `due` domain excludes claims and
  `claimed` is its own filter. Both chips added; the claim now reads as its own state.
- **Revise / Reset to Draft were offered while a claim was open**, which the server refuses.
- **`Delete Draft` was an orphan** — `deleteInvoice` exported, called by nothing.
- Zero-rate and finalize confirmations; the task picker now obeys Include Task Types; the
  client picker groups; `All unbilled` is the default preset; `empty_reasons` is rendered.

## 2. KPI Action Board — `f107673`, `684420f`, `d7738e6`, `4ae1ffd`

**The estimate overrun now explains itself on the card.** `/kra_kpi/tasks/get` has always sent
`estimate_extend_reason`, `estimate_extension_count` and `estimate_extended_by_name` — its own
comment says they are "carried to the card so the overrun explains itself instead of sending
someone to the audit log" — and the app read none of them.

**The view switch was slow for a reason unrelated to data.** Nothing is fetched or regrouped on
toggle. The board subtree unmounted and remounted, replaying the lane cascade in full: nine lanes
at `delay: index*80` plus 380 ms, so the last column did not arrive until ~1 s after the tap,
while the body sat at opacity 0. The cascade now plays on first sight only, and the fade starts
at 0.6 so the screen never blanks.

Underneath that, **neither view virtualised anything** and there is no cap on the task list — an
admin's server-side domain is `[]`, so 639 tasks meant 639 cards in one synchronous commit. Lane
bodies are `FlatList`s now, and the list view is one flat list over headings and rows together.
Cards are memoised, which required `nowMs` to stop reaching tasks that are not running: a
one-second tick was re-rendering every card for one task's seconds column.

**Gradients took three attempts and the first two were wrong.** `width="100%"` resolves against
the SVG viewport as it was when the rect laid out — for an auto-width button, before its label has
measured — so the fill stopped short. Measuring with `onLayout` fixed the width but only after a
state round-trip that landed seconds later, which is the "colour changes after 3–5 seconds" that
was reported. It now ramps top-to-bottom over the fixed 36 px height with an oversized clipped
width, correct in the first frame.

`AppDialog` replaced `Alert.alert` across the board, and the screen's own amber error modal
folded into it — it previously asked questions three different ways.

## 3. Workday note — `a48406b`, `7d6005b`

**The note was write-only in the app.** It validates, stores on the session, freezes onto the
snapshot, is drawn into the PNG and posted to WhatsApp — and was readable nowhere in the app.
`ea1cf80` added the block to the web snapshot and skipped `WorkdaySnapshots.js`.

**And it silently blocked logout.** The note required two real words, so typing `Finished` and
pressing `Logout & Send Summary` did nothing visible: the refusal rendered beside the note box,
far above the button. A field labelled `(optional)` was compulsory the moment anything went into

muted hint. The server has never refused a day over its note, so this is the client agreeing.

## 4. Live Tracking — `7d6005b`

**A failed background poll blanked the whole board.** `error` was set from the catch regardless of
the `silent` flag, and the render checks `error` before `rows` — so one flaky fifteen-second poll
replaced a populated board with a Retry screen. On a screen whose entire job is "who is working
right now", bad wifi looked exactly like everyone having gone home. Silent failures now only mark
the board stale; `as_of` is finally rendered, so a frozen board and a live one are
distinguishable. Away notes and reopen reasons are no longer clipped to two lines.

## 6. "Today" lane — module side, **uncommitted**

Start task 1 → pause → task 2 → pause → task 3, then go back to task 1: that meant hunting
through 121 paused tasks where one paused ten minutes ago looks identical to one paused three
weeks ago.

**Nothing in the payload could tell them apart.** `timer_start_datetime` is cleared on pause and
gated on `in_progress`; `timer_total_seconds` is a lifetime figure. So the module had to answer it
first.

`kpi.time.log` already is the fact table — one row per start→pause segment, with **`work_date`
stored, indexed, and computed in the developer's timezone** so 01:00 IST files under today. The
board already `read_group`s that table with no date filter, so a second date-filtered
`read_group` beside it emits **`today_seconds`** per task: one extra query for the whole board,
free "most time today first" ordering, and — because `work_date` simply stops matching —
**the midnight reset needs no cron and nothing to clean up.**

Web board gets a `🕒 Today` column, **first**, in indigo (`#4f46e5`) because Today is not a
workflow state and should not sit in the warm ramp the states use. A task appears in Today **and**
its status column: it is a shortcut, not a new home, so `Paused 121` stays truthful.
`getTotalTaskCount()` and `getTotalFilteredCount()` skip it — otherwise a 40-task board would
have reported 43.
