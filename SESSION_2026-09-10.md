## 1. KRA Report — the New Task modal

**Trimmed 21 fields to 11 inputs.** Removed the three reminder fields, Checklist, Guidelines and
all eight flags (Mandatory, Auto-assign, Auto-estimated, Permanent, Service KPI, Meeting,
Coordinator review, Customer review). Each was checked before removal: across every `.py` and
`.xml` the flags appear **only** in a form view and one serialiser — they render as badges and gate
nothing — and no cron or Python path reads the reminder fields at all.

**Added Type (REQ / UPT / BUG).** `create_kpi` now takes a `doc_type` and mints the ref through the
module's own helpers — `REF_PREFIX_FOR_DOC_TYPE` (`kpi_workflow.py:62`) and `_next_ref_for_prefix`
(`kpi.py:740`) — applying the `[Bug] ` / `[Update] ` name prefix the Accept path uses.

> **Why this mattered more than it looked.** Refs were already being minted, by
> `KpiWorkflow.create` → `_auto_admin_accept`, which defaults to `REQ` when no type is given. So
> before this change *every* task created from the report was a REQ whether or not it was one — and
> since the report matches types on that prefix, a bug you filed could never be found by the BUG
> filter.

**Added Time worked**, written by a new `kra.kpi.log_manual_time()`. Worked time lives in **two
places that are not derived from one another**: `timer_total_seconds` on the task (what the report's
Time Worked column and every total read) and `kpi.time.log` rows (what decides whether a task
matches a date range). `kpi_time_log.py` never touches the former. Write only the log and the
report shows 0h; write only the total and the task is invisible to its own date range. Both happen
in one call.

Filed against **today**, not the deadline — a deadline is a future date, and filing already-done
work against it pushed the hours into a month that had not happened yet.

**Mandatory now:** Task Name, Project, Assignee, Type, Estimate, Time worked — with an asterisk on
each. Assignee became mandatory as a consequence of Time worked: a log is attributed to a person
and feeds invoicing. Description stays optional; it is free text that drives nothing.

## 2. KRA Report — Download options

Added **A week** (with a proper ISO-week matcher, tested against the year-boundary cases:
`2025-12-29 → 2026-W01`, `2027-01-03 → 2026-W53`), **Sort by** (task name / KRA path / employee /
time worked / deadline) and **Only rows with time worked**.

**And found a real defect.** `confirmDownload` passed the dialog's filtered rows **only to the
ZIP** — pdf and excel were called with no arguments and rebuilt straight from the table:

```js
if (d.kind === 'zip') await this._runZip(d.include, this._rowsForDownload());
else if (d.kind === 'pdf')   await this.downloadPDF();      // no rows
else if (d.kind === 'excel') await this.downloadExcel();    // no rows
```

So none of Who / day / month / sort / worked-only reached those two formats — including **Who and
Period, which shipped on 9 Sep**. Pick "A month" and the PDF still contained everything. Fixed by
overriding the single row source (`_downloadRows`) for the duration of the build, so the summary,
the totals and each section cannot disagree with the rows printed beneath them.

Proven by downloading a real `.xlsx` through Chrome and reading it back: before `1.02, 2.5, 0.0`
(unsorted, 0h row present) → after `2.5, 1.02`.

## 3. KPI Action Board

- **Lanes with work come first**, empty ones fall to the end. That logic existed but only ran under
  a search; it now always runs. "Most tasks first" stays search-only — applying it unfiltered would

## What is NOT proven

**The card-clipping fix is not a fix.** Raising the card from 248px to 292px helps only the small
cluster of cards. Measured across the live board:

```
content height needed:  min 288 · median 509 · max 509   (box is 292)
still overflowing:      560 of 653 cards
```

A typical card needs **509px** — nearly double the box. No sensible height solves that; a 509px
card shows two per screen. What did change is that the boundary now fades instead of slicing a line
in half, so it reads as truncation rather than as broken text, and hover still expands the card.
The real options are to trim what the card carries (the description and per-user time lines are
most of the 509px), or to let cards size to content and accept the ragged lanes the fixed height was
introduced to remove.

**The red rule marks the backlog, not what is new.** "Never started" hits **47 of 58** Regular
cards. A 24-hour rule would mark 5. Built as specified, but when most of the board is red, red
stops meaning anything.

**Nothing here is committed.** Three files are modified in the working tree:
`kpi_action.js`, `kpi_kra_report.js`, `kra_style.scss`.

### Worth knowing

Deploying is three separate things, and getting one wrong wastes a round trip:

| Changed | Needs |
|---|---|
| Python | copy to addons **and restart the service** — `-u` in a separate process leaves the running server on the old `.py` |
| `__manifest__.py`, new fields/models | a module upgrade |
| JS / SCSS | `DELETE FROM ir_attachment WHERE name LIKE 'web.assets_%'`, then request the page **and its `/web/assets/...js` URL** to force the rebuild |

The bundle is rebuilt only when its own URL is requested, so a user clicking a button in an
already-loaded page keeps running the old code. Twice this week a change was reported as delivered
while the served bundle still held the old build. Grep the rebuilt bundle for a marker before
saying it shipped.
